# 方寸 · AI 动作交互约定

日期：2026-10-11。范围：HTML 交互设计，未接入原生输入法或真实模型。

## 核心关系

把固定的「中文 → 英文」推广成「输入内容 + 选定动作 → 结果 → 选取并上屏」。翻译是预设动作之一，模型提供文字处理能力，输入法负责保持输入习惯和返回原输入位置。

继续使用现有临时编辑区。没有独立工作空间、后台、文件管理或第二套应用导航。

Tab 顺序为「改文字」「问 AI」。打开页面默认选中第一个 Tab「改文字」，初始动作是「翻译成英语」，之后记住上次选择的动作。刷新回到「改文字」，不恢复草稿、不自动执行。底部体验入口以「默认译英」排第一；「默认译英」和 `#transform` 可直接进入英语转换场景。

| 入口 | 用户想做什么 | 内容如何流转 |
| --- | --- | --- |
| 问 AI | 问问题、起草回复、整理计划、根据资料写内容 | 问题 + 可选参考文字 → 回答 → 追问 / 选择 / 修改 / 复制 / 插入 |
| 改文字 | 翻译成不同语言、润色、提取信息、自定义格式 | 原文 + 一个动作 → 处理结果 → 修改 / 复制 / 插入 |
| 输入法浮窗 | 打字时临时使用 AI | 完成选词的草稿 →「问 AI」或「改文字」→ 展开编辑 |

“干活”在此稿中指生成和处理文字。联网查询、文件工具、执行外部操作不在本轮 HTML 原型中；将来接入时，需要呈现实际执行步骤、来源及成功 / 失败反馈，不能把生成回答当作已执行操作。

## 结果与上屏

- 结果区可编辑。选中文字后，复制和上屏按钮同时变为「复制选中」「插入选中」，显示选中字数；取消选中恢复全文。
- Cmd + Enter 插入结果；有选区时只插入选中结果。原输入框有选区时替换原选区，否则插入光标处。动作不会发送消息。
- 改文字模式可用 Cmd + Shift + Enter 直接上屏原文；问 AI 模式不默认插入问题本身。
- 成功后收起浮窗、把焦点还给原输入框；保留本次草稿和回答，可再打开。演示提供撤销插入，原输入框有后续编辑则不再撤销，以免覆盖新内容。
- 收起不等于上屏。Esc 或关闭按钮只保留并收起。
- 原框内容或选区改变时禁止静默插入。重新定位原输入框并点击「唤起方寸」，明确绑定新位置。
- HTML 只模拟一个宿主 textarea。真实跨进程目标与焦点交接继续由 build 21 的原生实现负责，不能用页面内插入测试代替系统级验收。

## 调用与状态

| 情况 | 行为 |
| --- | --- |
| 输入、选词、空格、换行、切换动作、保存指令 | 不请求模型 |
| Ctrl + Enter / 点击执行 | 主动执行一次 |
| 尚在中文合成中 | 不执行，不上屏，等待完成选词 |
| 请求进行中 | 可停止；结果上屏和追问暂不可用 |
| 原文或参考资料变化 | 取消进行中的请求；旧结果标记失效，不自动重跑 |
| 修改结果 | 按修改后的内容复制 / 插入；不请求模型 |
| 追问 | 沿用当前问题、资料及选定版本，产生新的回答版本 |
| 选择旧版本 | 可取用旧结果；后续追问以选定版本为基础 |
| 失败 | 保留输入和已有结果；只在主动重试时再次请求 |

Ctrl + Shift + Enter 沿用现有临时编辑区的唤起方式。问 AI 与改文字各自保留本页草稿，切换页签不会丢掉另一边的内容。

## 自定义动作

每个动作包含：名称、可选 `/key`、特殊指令。预设包括翻译成德语、翻译成英语、提取约定、说得自然点。编辑内置动作时另存为“我的”版本，自定义动作可继续编辑。

`/key` 是动作菜单内的检索别名，不在普通中文输入过程中截获斜杠或破坏拼音 / 英文混输。

原文自动附在指令之后，不要求用户写变量模板。指令留空时默认按原文中的明确要求处理；没有明确要求则保留原文。保存只更新配置，不发起处理。正式实现需把动作指令、用户材料与会话上下文分开组装，避免原文被误当成系统指令。

自定义动作保存在本浏览器 localStorage；输入、参考文字与回答仅存在本页内存，刷新即清空。不会读取原生模型配置、API Key 或已有输入法草稿。

## 演示边界

- 底部的问答、德语、提取信息示例返回固定内容；“帮我缩成一句话”对默认问答提供一条固定追问结果。
- 非样例输入、自定义指令和任意追问返回明确的交互占位提示，不伪装成真实推理、翻译或提取。
- 可以手动编辑结果，验证任意文本的选中、复制、直接插入路径。
- 无网络模型请求，不查询网页，不自动操作外部应用。复制 / 粘贴使用浏览器剪贴板权限；不允许时提示使用系统快捷键。
