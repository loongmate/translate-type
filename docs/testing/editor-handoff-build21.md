# 编辑区与宿主之间的焦点交接 · build 21

日期：2026-10-11。

## 本次真实日志对应的问题

用户反馈原文按钮仍灰、确认光标无反应，以及回原框再打一个字才出现编辑内容。查阅 `~/Library/Logs/FangCun/editor-focus.jsonl` 后，确认 build 20 在 Codex 客户端的状态如下；现场元数据已保存在 `.build/build20-user-focus.jsonl`，没有输入正文。

- 打开编辑区时，刚发出清除预编辑请求，就记录了 `[0,5]` 的选区和预编辑范围。稍后宿主才更新成 `[0,0]`。第二次打开也出现同类旧预编辑范围。
- 因为锚点捕获过早，程序一开始提示未完成选词，随后又把自己的清除结果判成光标变化。确认按钮在宿主更新之前仍读到旧预编辑，不能恢复。
- 现场没有 `commit-request` 或 `commit-dispatched`，无法据此说原文真正提交过。「上屏到：应用名」只是原来的目标标签，不是成功回执。
- 旧控制器在返回宿主后的任意按键上自动 `collapse()`，将编辑区草稿重新作为预编辑写回。代码路径与「再打一字才出现」的现象相符，但日志未记录完整的按键路径，故不将其表述为唯一原因。
- 实际客户端的唯一字符串连续读取不同、文档长度返回 0，即使光标位置不为 0。build 20 对缺少文档访问能力与不稳定标识的修正仍有必要，本次故障发生在后续交接时机。

## 改动

1. **打开放大编辑区**：先把编辑会话交给编辑区持有；清除自己在宿主中的预编辑；让触发快捷键的 IMK 回调返回。等待宿主报告预编辑已清空、光标到达预期位置后，才重新捕获目标并显示编辑区。不是简单延长固定等待时间。
2. **等待期间**：输入控制器的被动激活不能发送第二份空预编辑更新。有限时间内未完成就保留草稿并提示恢复，不静默删字，不假装准备完成。
3. **绑定光标**：按钮改为「重新绑定光标」，先释放面板焦点再读取当前目标。它只绑定，不插入。目标标签改为「目标：应用 · ⌘Enter 上屏」，避免被理解为已写入。
4. **上屏**：先隐藏编辑区、释放键盘焦点，让宿主处理恢复，再重新校验目标并调用 IMK。期间用户移动光标、切换会话或开始继续输入，就取消本次待提交并保留编辑草稿。连续 Cmd+Enter 不重复写入。
5. **返回原框打字**：不再隐式缩回并带出草稿。只有显式「缩小」/ Esc 才转交编辑会话；新输入与仍保留的编辑草稿分开。

不调用模型、不改剪贴板、不向用户应用合成按键来刷新界面。日志继续只记录元数据，`commit-dispatched` 仍仅表示发送了提交调用，不是显示成功回执。
