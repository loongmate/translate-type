# build 46：原子升级验证版

2026-11-05，Intel / macOS 14.7.4。本版尚未公开发布；当前公开版仍为 build 45。

## 修改

- 已安装应用保持原路径，包括已知的旧安装名。升级使用 `renameatx_np` / `RENAME_SWAP`，回滚也交换回原目录；首次安装使用 `RENAME_EXCL`，拒绝覆盖检查之后新出现的目标。备份先复制到 Installer/Backups，不移走注册路径。
- 选中方寸时先切到备用键盘，确认选择结果并给客户端停用通知留出处理时间，再请求旧进程正常退出。旧进程拒绝或超时则中止，不强制结束。
- 启动新版时使用后台普通启动，不创建额外实例、不打开升级设置页。核对唯一 PID 和安装路径，再等待新版就绪响应；响应核对随机请求、PID、版本、Bundle ID 和可执行文件路径。监听仅在 Rime 和 IMKServer 初始化完成后启用，不读取输入内容、配置、凭据或剪贴板。
- 启动成功后，仅恢复升级前已选中的方寸输入源，其他输入源保持用户原选择。覆盖升级不再一律返回需要重新登录。
- 启动、就绪检查或选择失败时尝试原子恢复旧版。旧版尚无就绪协议，回滚启动不强制等待它实现新协议。文件未替换时，恢复不额外拉起旧进程。
- 本机构建的 `scripts/install.sh` 与 DMG 复用相同安装服务，不再手写另一套移走旧目录、kill 进程的流程；保留 `FANGCUN_OPEN_SETTINGS=0`。
- 首次安装若系统尚未发现输入源，保留“需要重新登录”的独立结果，不宣称立即可用。

## 已验证

`./scripts/installer-test.sh`：66 项通过。含真实文件替换、快照、回滚、备份失败、首次安装目标竞争、原目录 inode 恢复、旧安装名路径保留、退出拒绝/超时、启动/选择失败，以及原生安装按钮。系统输入源、进程清单及失败注入采用替身。

路径连续性回归先在旧实现失败：100 次替换和回滚，独立线程 41,989 次观测中有 2,758 次路径不存在。改用原子交换后，同一场景多次运行均为零次缺失；首次通过运行 81,915 次观测。测试观察真实文件系统，没有在生产输入法目录中替换应用。

`./scripts/runtime-readiness-test.sh`：7 项跨进程检查通过。使用独立原生测试应用，验证初始化延迟、错误 PID、错误版本/标识/路径、并行随机请求和进程退出后的过期结果。该测试不注册输入源，不验证宿主 IMK 会话重连。

`FANGCUN_EDITOR_TEST=AppLifecycleTests ./scripts/editor-test.sh`：13 项通过，菜单与显式设置入口、普通 reopen、激活通知和 IMK 测试客户端切换行为保持。存在原有 SwiftUI onChange 弃用警告。

`FANGCUN_ARCHS='x86_64 arm64' ./scripts/build.sh`：两种架构构建通过。输入核心和方案资源未修改；新增的运行时协议只交换就绪元数据。

`./scripts/install.sh --help`：开发安装工具编译及帮助入口检查；未执行本机生产安装。

## 未验证与试验步骤

对方补充的实际环境是 **macOS Tahoe 26.6**。受影响范围是所有曾使用旧版方寸、升级时仍在运行的应用；不限定应用名称。此反馈描述此前的升级故障，目前没有收到 build 46 的现场测试结果。不能用新开的应用、重开的窗口或本机 macOS 14 的结果代替这个场景。

独立输入法身份的旧窗口探针，在升级之前首次选择测试输入源时返回 `TISSelectInputSource = -50`，退出码 77；没有进入替换阶段。因此它不算旧宿主升级通过，也不足以断言这是系统的升级硬限制。本轮没有停止或覆盖本机正在运行的生产方寸，也没有注销或重启系统。

现场验收必须保留多个已经连接过旧版方寸的应用及原窗口：

1. 在各应用的原输入框中先用旧版方寸输入，记录旧版版本和进程；保存尚未确认上屏的文字。保留这些应用及窗口运行，再运行适合芯片的 build 46 安装器。
2. 升级后逐一回到这些原输入框，检查 ABC 能输入、方寸能输入中文，以及双拼待选后直接按逗号得到中文候选和中文逗号。
3. 来回切换输入源与上述应用，再重复输入；确认设置页不自行弹出、紫色状态图标只有一个，且新版进程与安装版本一致。
4. 全程不退出上述应用、不重开原窗口、不注销或重启 macOS。若任何原输入框必须通过这些操作才能恢复，即判定旧宿主升级验收失败。

安装器元数据就绪与 TIS 可选只证明对应检查，不能替代旧宿主重新建立 IMK 会话的验收。现有证据尚不能确认 Tahoe 26.6 的故障根因，也不能确认 build 46 已修复该场景。

此结果通过之前，不标记为已验证的无缝升级版，不发布新的 GitHub Release。
